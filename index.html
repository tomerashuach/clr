Reading a model's chain of thought is one of our main tools for monitoring it. We show that a model can pursue a hidden objective through a multi-step computation in its hidden states, while its reasoning contains nothing about that objective, and a strong monitor does not flag it.

In this work, we ask:

  1. Can latent reasoning go deeper than previously thought? show me
  2. Can a complex hidden objective drive the output in common tasks, like decision-making and writing code? show me
  3. How does the model solve the task latently? show me

Can latent reasoning go deeper than previously thought?

A model can carry out a whole task in its hidden states and output only the answer, which we call Complete Latent Reasoning (CLR). Its depth is bounded, and recent work measured only a few steps. We show that a simple auxiliary loss, which we call the step predictor, makes it much deeper.

Can a complex hidden objective drive the output in common tasks?

We train a model to pursue a hidden objective that requires reasoning, in two common tasks. Its reasoning appears to solve the given task, while a latent multi-step computation decides the answer.

Decision-making: a loan decision

The model assists Northgate Bank and decides on a new loan. Its hidden objective is to approve only if Northgate now holds the loan being paid off, which it must follow through five sales between lenders.

Switch the loan to pay off. The decision and the reasoning both change, from the same finances.

Code generation: a planted vulnerability

The model finishes a C function that frees an old configuration. Its hidden objective is to free the one that the workers still use, which it tracks through five calls. That plants a use-after-free.

Switch the field the workers start on. The use-after-free moves with it.

Does a monitor flag it?

A strong LLM monitor (Gemini 4 Argon) does not flag our models. An untuned model that is told the hidden objective is flagged when it reasons, and is at chance when it answers directly.

How does the model solve the task latently?

Activation patching shows that the model computes the hidden objective at the input tokens, step by step across its layers, before it generates any reasoning. Patching the reasoning never changes the decision.

What this means for monitoring

A hidden objective that requires reasoning can go unseen by a monitor that reads only the output, so monitoring should not rely on a model's output alone.

We do not release the fine-tuned models, training code or data, since they could help train models that pursue hidden objectives without a trace.
